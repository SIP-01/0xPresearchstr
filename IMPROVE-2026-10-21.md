## Top recommendations (ranked, with effort S/M/L)

1. **NIP-01 empty-filter compliance in `backend/nip50-relay` (S).** Upstream changed *this week*: #2504 (2026-10-17) — empty filter lists match nothing; #2511 (2026-10-20) — clients must not send empty lists. The relay's `isNostrFilter` accepts empty arrays (only `length > 100` is rejected), and `buildMeiliFilter` only adds a condition when `field.length > 0` — so a REQ with `{"kinds": []}` currently produces *no* kind constraint and matches **everything**: exactly the match-all semantics NIP-01 just explicitly killed. Fix: if any list field is present-but-empty, immediately return EOSE/zero results for that filter; also re-check `limit: 0` handling against #2460 (2026-09-04). This is a spec-compliance bug in shipped code — fix first.
2. **Make the PR #2 process the rule, not the exception (S).** PR #2's 19 fixes (SSRF, squatting, malformed-REQ crash, revocation, test gate) landed via one big reviewable PR — good. But `main` is still unprotected and `deploy.yml` fires on push-to-main. Add: branch protection (1 review + required checks) and a `pull_request` CI trigger running `npm ci && npm test && npm run build` (PR #2 already repaired `npm test` — now gate on it).
3. **Port the fixes back to 0xSearchstr or consolidate (M).** PR #2's fork-independent fixes (squatting verify-before-group, RepoView clone quoting, admin revocation, router basename, provider dedup/cache-key bugs, account-switch relay leak) were verified absent from 0xSearchstr main this session. Recommended path: cherry-pick now (S), extract shared `@sip01/search-core` (M), then either differentiate or archive one engine (governance S). Keeping both unfixed-ish copies live guarantees repeated double-maintenance failure.
