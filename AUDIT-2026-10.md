# Security Audit — SIP-01/0xPresearchstr — 2026-10-20

## Summary

Fork-of-record of 0xSearchstr adapted for Presearch, monetized with Precommunity keyword ads via a Cloudflare Worker (`worker.ts`). This repo is the **security leader of the family**: PR #2 (merged 2026-10-14, author thewayofdev, reviewed by CodeRabbit + full test suite) shipped `docs/CODE-REVIEW.md` — a 19-finding audit with fixes for SSRF, relay DoS, observation squatting, privacy-mode AI leaks, and more. The ad integration is well built: `KEYWORD_MARKET_API_KEY` is a Wrangler secret only (never in source, `VITE_*`, logs, or responses — pinned by tests), the worker whitelist-validates ad fields, forces HTTPS, pins click/report links to `precommunity.org`, rejects redirects carrying the key, applies per-IP rate limits, and fails closed when unconfigured. **No API keys or nsec committed.** Residual risk: the backend `docker-compose.yml` still ships `change-me` default credentials (same flaw as 0xSearchstr), and ad resolution is an intentional Privacy Mode exception (disclosed in UI, but it does send the query text to the operator backend).

**Counts: 1 CRITICAL / 1 HIGH / 1 MEDIUM / 2 LOW**

## Findings

| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| PRE-1 | CRITICAL | `docker-compose.yml` | Same dangerous defaults as upstream: `MEILI_API_KEY:-change-me` (Meilisearch master key `change-me` + host port 7700) and `ABUSE_ADMIN_TOKEN:-change-me` (enables admin API with a publicly known token; admin can delete index documents). A default `docker compose up -d` deployment is remotely administrable | Use `${VAR:?required}` (fail-closed), remove `ports:` for Meilisearch, document random token generation |
| PRE-2 | HIGH | `backend/abuse-api/src/index.ts` | `Access-Control-Allow-Origin: *` still on all endpoints including admin (PR #2 fixed body-limit/removal ordering but not CORS) | Restrict CORS to the frontend origin; no `*` on admin routes |
| PRE-3 | MEDIUM | Privacy model | PRE community ad resolution stays active in Privacy Mode: eligible Web/All query text goes to the engine backend (operator sees query + IP; upstream gets query only). It IS disclosed in Settings/About/PrivacyIndicator and excluded for nsec/NIP-19/NIP-05/URL/math classes | Acceptable if deliberate; consider an opt-out toggle for the ad exception |
| PRE-4 | LOW | `docker-compose.yml` | Unpinned `:latest` images (`dperson/torproxy`, `purplei2p/i2pd`); Tor SOCKS 9050 + i2pd console 7070 published on host | Pin digests; don't publish proxy/console ports |
| PRE-5 | LOW | PR process | PR #2 (90 files, +2658/−1316) merged same-day by owner; it had CodeRabbit review + tests, but no human second review | Branch protection: 1 human approval for large PRs |

## Secrets Check

- GHAS secret scanning not enabled (org-wide gap); compensated with org code searches (`nsec1`, `sk-`, `xai-`, `pkm_`, `api_key`, `PRIVATE KEY`): only placeholders and test fixtures (`pkm-fake-server-secret` in tests — fake). **No live secrets.**
- `.gitignore` covers `.env`, `.env.*` (except `.env.example`), `.dev.vars`, `.wrangler/`. README correctly instructs `wrangler secret put KEYWORD_MARKET_API_KEY` and "never prefix with VITE_".
- Worker anti-leak tests assert the API key never appears in any response or upstream error echo.

## Dependency Notes

Same modern stack as 0xSearchstr; PR #2 moved `tsx` into production deps so containers don't download it at startup (supply-chain improvement). No git-URL deps, no wildcards, no unjustified CVE flags.
